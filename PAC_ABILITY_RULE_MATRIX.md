# PAC Ability Rule Matrix

This document is the clean-room rules reference for Grand Line Auto Chess abilities. It is pinned to Pokémon Auto Chess commit [`b6ade5d464fa8a88f309ec016c0c81693ea5227d`](https://github.com/keldaanCommunity/pokemonAutoChess/tree/b6ade5d464fa8a88f309ec016c0c81693ea5227d); links below are immutable GitHub permalinks to that commit.

No PAC source code, assets, balance values, or random-number implementation are copied into Grand Line Auto Chess. PAC strategy names appear only as source attribution; the implementation remains original and uses Grand Line's types, fixed-tick engine, events, balance, and presentation.

## Shared combat contract adopted in Phase 8A

- PAC checks a unit's shared action cooldown before moving, attacking, or casting. A targeted ability replaces a basic attack only when its target is alive and in the unit's normal attack range. See [AttackingState](https://github.com/keldaanCommunity/pokemonAutoChess/blob/b6ade5d464fa8a88f309ec016c0c81693ea5227d/app/core/attacking-state.ts).
- An ability whose strategy declares that it does not require a target may be cast from the movement state without walking into attack range. See [MovingState](https://github.com/keldaanCommunity/pokemonAutoChess/blob/b6ade5d464fa8a88f309ec016c0c81693ea5227d/app/core/moving-state.ts).
- The normal PAC ability path spends energy and resolves immediately. Only an individual strategy may schedule delayed work; there is no universal cast wind-up. See [AbilityStrategy](https://github.com/keldaanCommunity/pokemonAutoChess/blob/b6ade5d464fa8a88f309ec016c0c81693ea5227d/app/core/abilities/ability-strategy.ts), [castAbility](https://github.com/keldaanCommunity/pokemonAutoChess/blob/b6ade5d464fa8a88f309ec016c0c81693ea5227d/app/core/abilities/cast.ts), and [DelayedCommand](https://github.com/keldaanCommunity/pokemonAutoChess/blob/b6ade5d464fa8a88f309ec016c0c81693ea5227d/app/core/simulation-command.ts).
- Grand Line intentionally keeps energy clamped to **0–100** and resets it to **0** on cast. PAC can preserve energy above the maximum after spending; that overcharge behavior is not adopted.
- Grand Line never adopts PAC's [`Math.random()` helpers](https://github.com/keldaanCommunity/pokemonAutoChess/blob/b6ade5d464fa8a88f309ec016c0c81693ea5227d/app/utils/random.ts). Every random choice uses the battle's seeded PRNG. All equal-score choices use stable entity ID and cell-coordinate tie-breaks so replay results remain deterministic.
- `castAnimationMs` is presentation-only. Delays, channels, repeated hits, movement, refunds, and failure behavior become authoritative only when explicitly listed for that character below.

## Decision gate for later signature passes

Before implementing any row marked **Open**, compare the pinned PAC strategy, its user-facing description, and Grand Line's current combat behavior. If they conflict or more than one PAC analogue remains viable, request a gameplay decision rather than silently selecting a rule. Once decided, replace the open note with the exact adopted geometry, timing, collision, failure, status, and deterministic tie-break behavior.
